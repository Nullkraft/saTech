Serial receive work completed
-----------------------------

- Added SerialRxMode: AsciiLineData, BinaryControlWord, FMNData, Direct2Register.
- Added serialRxState to track current receive mode, selected binary target,
  4-byte word buffer, and byte count.
- Renamed binary chip-select helper to selectChipBinary().
- Renamed binary control-word dispatcher to handleControlWord().
- pollSerial() now treats the serial stream as byte-oriented and documents the
  ASCII-vs-binary decision branches.
- Binary control-word receive now starts only on raw 0xFF at the ASCII frame
  boundary. Non-printable bytes other than 0xFF no longer start binary
  collection in AsciiLineData mode.
- Binary 4-byte control frames route through handleControlWord().
- ASCII hex control words now dispatch into handleControlWord() from firmware
  ASCII command handling.
- The ASCII hex parser was simplified after bring-up: a single ASCII token is
  parsed and passed to handleControlWord() without local format policing. Bad
  or poorly formatted values are intentionally allowed through; technician
  correction or the next sweep step can clean them up.
- Added host-side ASCII command mapping tests and test/run_ascii_tests.sh for
  ASCII equivalents of the message and reference control commands.
- Quiet mode-selection control words implemented:
  - 0x06FF enters AsciiLineData.
  - 0x0EFF enters FMNData.
  - 0x16FF enters Direct2Register.
- Mode-selection control words update serialRxState.mode and clear the partial
  word buffer without printing.
