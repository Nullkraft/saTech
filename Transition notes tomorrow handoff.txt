Current receiver shape
----------------------

- Transport encoding is separate from payload mode.
- Transport enum: SerialTransportEncoding::Ascii / Binary.
- Payload enum: SerialPayloadMode::Command / FMNData / DirectRegisterData.
- saTech.begin(token) accepts ascii/binary capitalization variants, returns
  false for unsupported tokens, and ignores unsupported encodings.
- setup() currently starts with saTech.begin("ascii").
- pollSerial() dispatches by configured transport encoding:
  - Binary path: collectBinaryByte(uint8_t).
  - ASCII path: collectAsciiByte(char, uint8_t).
- Both paths now produce complete uint32_t words and call
  processReceivedWord(uint32_t).
- processReceivedWord() classifies any completed word with LS byte 0xFF as a
  command; otherwise it uses the current payload mode.
- Current processing handles Command and FMNData. DirectRegisterData mode can
  be selected, but direct-register word handling still needs implementation.

Important protocol facts
------------------------

- Wire byte order for binary words is little-endian.
- ASCII tokens are parsed as hex into uint32_t with strtoul(token, ..., 16).
  Example: "17FF" becomes 0x000017FF, so low-byte checks happen on the parsed
  word, not on raw string bytes.
- FMN packed data: F=[31 downto 20], M=[19 downto 8], N=[7 downto 0].
- FMN N is guaranteed never to be 0xFF.
- Direct register data is a 32-bit register word; Addr=[2 downto 0].
- Direct register data LS byte is guaranteed never to be 0xFF.
- Command/control data: data=[31 downto 16], command=[15 downto 11],
  address=[10 downto 8], command_flag=[7 downto 0].
- command_flag is always 0xFF. command data bits are currently unused but must
  remain accounted for.

Mode command words
------------------

- Enter command mode: 0x000006FF.
- Enter FMN data mode: 0x00000EFF.
- Enter direct register mode: 0x000016FF.
